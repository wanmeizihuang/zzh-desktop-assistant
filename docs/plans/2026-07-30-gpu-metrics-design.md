# GPU 与显存监控设计

**日期：** 2026-07-30  
**阶段：** P1 技术验证  
**目标平台：** Windows 10/11 x64

## 目标与边界

本阶段把真实 GPU 利用率和显存占用接入现有 2 秒采样循环，继续保持低 CPU、低内存和无常驻子进程。温度不在本阶段范围内，界面继续明确显示“待接入”，不得用估算值代替传感器值。

GPU 与显存是两个独立能力。任一数据源初始化或采样失败时，只降级对应指标，其他 CPU、内存、网络及另一项 GPU 指标继续刷新。

## 数据源比较

### 方案 A：Windows PDH + DXGI（采用）

- GPU 利用率读取英文 PDH 路径 `\\GPU Engine(*)\\Utilization Percentage`。
- 使用 `PdhAddEnglishCounterW`，不依赖 Windows 显示语言。
- 显存通过 PDH 的 `Dedicated Usage` 与 `Shared Usage` 读取全系统当前用量；DXGI 负责枚举硬件适配器、提供 LUID、容量与预算。
- 优点是厂商无关、无需外部程序、可复用当前采样线程。
- 风险是旧驱动或精简系统可能不暴露 GPU Engine 计数器，届时应显示“不可用”。

### 方案 B：仅使用性能计数器

GPU Engine 与 GPU Adapter Memory 都可由 PDH 获取，实现表面上统一。但显存计数器难以可靠获得硬件总容量，且适配器身份与筛选信息不足，因此不采用为主方案。

### 方案 C：厂商命令行工具

`nvidia-smi` 等工具适合交叉验证，但会引入厂商限制、进程启动开销和部署依赖。本机未发现 `nvidia-smi`，所以它不作为产品依赖，也不作为本阶段验收前提。

## 聚合语义

PDH 为每个进程和 GPU 引擎返回一个实例。采样器从实例名提取 `luid + phys + eng` 身份，先把同一物理引擎上的进程占用相加并限制在 0% 至 100%，再取所有适配器中最忙引擎的值。不能直接把全部实例相加，否则不同并行引擎会产生超过 100% 的误导结果。

显存只展示一个适配器，选择规则固定如下：

1. 排除 `DXGI_ADAPTER_FLAG_SOFTWARE` 软件适配器。
2. 每次采样优先选择当前 GPU 内存用量最大的适配器，以跟随混合显卡的实际活动设备。
3. 所有适配器当前用量相同时，优先选择 `DedicatedVideoMemory` 最大的适配器；专用容量仍相同时，再选择两段预算合计最大的适配器。
4. 当前用量为 PDH 专用与共享用量之和，总量为 DXGI 报告的专用显存与共享内存上限之和；驱动未报告容量时才回退到两段预算之和。

这个口径优先表达用户主要 GPU 的总 GPU 内存压力，同时让只使用共享内存的集显也能显示真实用量；不同适配器仍不会混为一个不可解释的总数。当前用量最终限制在显示总量以内，防止驱动瞬时返回不一致值导致百分比超过 100%。

## 组件与数据流

`SystemSampler` 增加 Windows 专用 GPU 与显存采样器，并缓存 DXGI 硬件适配器身份和容量。构造时打开两个独立 PDH 查询、注册通配符计数器并采集第一帧作为差分基线，同时枚举一次 DXGI 适配器。后续每次 `sample()`：

1. 采集下一帧 PDH 数据并生成 GPU 百分比。
2. 读取各适配器的 PDH 专用与共享用量，按 LUID 关联 DXGI 容量并选择当前最活跃适配器。
3. 与 CPU、内存、网络一起生成 `MetricSnapshot`。
4. UI 线程只接收快照并格式化文本，不执行系统 API。

`MetricSnapshot` 新增独立的 `gpu_total_percent: MetricValue<f32>` 与 `video_memory: MetricValue<VideoMemoryUsage>`。PDH 还未形成有效差分时状态为 `WarmingUp`；数据源不存在、查询失效或没有有效实例时为 `Unavailable`。

## 错误处理与资源约束

- PDH 查询句柄由 RAII 类型持有，退出采样线程时调用 `PdhCloseQuery`。
- DXGI 接口由 `windows` crate 的 COM 智能指针管理，不创建额外线程。
- 通配符结果缓冲区仅在每次 2 秒采样时短暂分配；后续可在性能数据证明必要时复用。
- 不启动 WMI、PowerShell 或厂商工具子进程。
- 计数器无实例、状态无效、DXGI 枚举为空均按真实不可用处理。

## 测试与验收

- 单元测试覆盖同一引擎多进程求和、不同引擎取最大值、异常值限制和无法解析实例名。
- 单元测试覆盖独显优先、UMA 预算回退、软件适配器排除。
- UI 格式测试覆盖 GPU 百分比、显存用量/总量、预热和不可用状态。
- 本机探针连续输出至少三次快照，确认 GPU 与显存不再显示伪造或固定值。
- 完成 `cargo fmt --check`、严格 Clippy、全 workspace 测试和 release 构建。
