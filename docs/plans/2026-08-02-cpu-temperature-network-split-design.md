# CPU 温度与网络上下行拆分设计

日期：2026-08-02
状态：已确认

## 目标

- 新增低占用的 CPU 温度监控。
- 将当前合并的网络卡片和网络趋势拆成下行、上行两项。
- 保持 412 x 640 的展开窗口尺寸和现有采样频率策略。

## 数据采集

CPU 温度使用 Windows 原生 `Thermal Zone Information(*)\Temperature` 性能计数器。采样器随 `SystemSampler` 创建并复用同一个 PDH 查询，不创建额外进程或常驻服务。计数器返回开尔文温度，转换为摄氏度后仅接受 0 至 150 摄氏度的有限值；存在多个热区时取有效值中的最高值。

原生热区不能保证所有设备都提供 CPU Package 传感器，因此界面明示数据为“ACPI 热区”。计数器不存在时显示“不支持”，已初始化的数据源暂时读取失败时显示“暂不可用”，不使用主板、GPU 或其他传感器数值冒充 CPU 温度。

网络仍通过一次 `GetIfTable2` 调用汇总活动物理网卡。现有 `NetworkThroughput` 同时携带接收与发送速率，不增加系统调用；拆分只发生在桌面端格式化、属性绑定和趋势模型中。

## 界面布局

监控卡片改为固定尺寸的两列四行：

```text
CPU       CPU 温度
内存      显存
GPU       GPU 温度
↓ 下行    ↑ 上行
```

卡片高度压缩但保留标签、主值和说明三层信息。下行固定使用蓝色，上行固定使用红色。最近 5 分钟趋势保留 CPU、内存，并将网络拆成独立的下行和上行曲线；两条网络曲线共享同一峰值比例，方便直接比较流量大小，缺失采样继续留空。

## 验证

- 单元测试覆盖开尔文到摄氏度转换、异常值过滤、多热区最高值选择和不可用状态。
- 桌面端测试覆盖上下行文本拆分、共享比例归一化和独立趋势模型。
- 运行工作区测试、严格 Clippy、格式检查和 Release 构建。
- 界面位置、文字、颜色和裁切由用户按人工步骤确认。
