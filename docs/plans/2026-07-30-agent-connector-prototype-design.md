# 智能体连接器原型设计

**日期：** 2026-07-30  
**阶段：** P1 技术验证  
**关联决策：** ADR-0003 能力驱动的智能体连接器

## 目标与边界

本阶段验证 HTTP 与本地 CLI 两类智能体能否遵守同一套流式调用契约。交付物包括核心协议、可脚本化 HTTP 模拟器和启动真实测试子进程的 CLI 连接器。它不连接外部网络、不保存凭据、不读取附件内容，也不把模拟响应接入正式对话 UI；真实 OpenAI 兼容接口、Codex CLI 参数和界面状态机属于 P4。

## 方案比较

### 异步 trait 与异步流

真实 HTTP 的表达最自然，但会让核心契约直接依赖 Tokio、Futures 和对象安全辅助层。桌面 UI、测试和本地 CLI 都必须进入同一异步模型，P1 的依赖与资源结论会被提前放大。

### 同步回调

依赖最少，但回调容易在连接器线程中重入调用方，取消、背压和生命周期难以统一，也不适合 Slint 事件循环。

### 运行句柄与事件通道（采用）

`AgentConnector::start` 立即返回 `AgentRun`。运行句柄包含标准库 MPSC 接收端与共享取消令牌；连接器在自己的工作线程或未来的异步运行时中发送事件。核心层不依赖具体运行时，HTTP 和 CLI 可以独立演进，UI 只需消费统一事件。

## 核心契约

`agent-core` 定义以下稳定边界：

- `ConnectorDescriptor`：稳定 ID、显示名称、传输类型和能力。
- `ConnectorCapabilities`：是否流式、附件模式、图片输入和本地执行。
- `AgentRequest`：调用 ID、消息列表和仅含元数据的附件引用。
- `AgentEvent`：`Started`、`TextDelta`、`Completed`、`Cancelled`、`Failed`。
- `ConnectorError`：配置、认证、限流、超时、传输、协议、进程和不支持能力等机器可读错误码。
- `AgentRun`：事件接收端与幂等取消操作。

附件默认不支持。连接器未声明对应能力时，请求在启动子线程、网络或子进程之前被拒绝。P1 不生成全局 UUID，由调用方提供单调递增的 `RequestId(u64)`。

## HTTP 模拟器

`agent-http` 提供 `MockHttpConnector`，用脚本描述成功分片、HTTP 状态错误、分片后断流和分片间隔。它不会打开端口或访问网络，只验证 HTTP 类连接器如何把上游结果映射为统一事件。401 映射为认证错误，429 映射为限流错误，其他状态与断流映射为传输错误。取消在下一个短轮询点产生 `Cancelled`，之后不得再发送文本或完成事件。

## CLI 原型

`agent-cli` 提供 `CliConnector`，配置只包含可执行文件路径和参数数组，不接受拼接后的 shell 命令。提示词通过标准输入传递，标准输出逐行转为 `TextDelta`，非零退出码转为进程错误，取消调用 `Child::kill` 并等待进程退出。Windows 使用 `CREATE_NO_WINDOW`，避免实际产品调用 CLI 时闪出控制台。

测试使用同包的 `agent-cli-fixture` 二进制，覆盖流式输出、非零退出、取消和包含 shell 元字符的提示词。这样验证的是真实进程管道，而不是另一个内存模拟器。

## 错误、资源与安全

- 启动前校验空消息和附件能力，失败不产生后台工作。
- 取消令牌只使用 `Arc<AtomicBool>`，无需常驻运行时。
- 每次调用最多创建连接器工作线程；CLI 额外创建有界生命周期的 stdout/stderr 读取线程。
- stderr 最多采集 8 KiB，防止异常子进程无限输出占用内存。
- 参数始终使用 `Command::args`，用户提示走 stdin，禁止 shell 解释。
- 所有线程在完成、失败或取消后退出，事件发送端随之关闭。

## 验收

- 核心契约测试覆盖能力拒绝、事件顺序、错误重试语义和幂等取消。
- HTTP 测试覆盖成功流、401、429、断流和取消。
- CLI 集成测试覆盖真实逐行输出、字面传递 shell 元字符、退出码和进程终止。
- 全 workspace 格式、测试与严格 Clippy 通过。
- 示例探针能打印两种连接器的统一事件序列，且不需要网络或凭据。
