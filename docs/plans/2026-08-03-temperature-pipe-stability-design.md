# 温度管道稳定性修复设计

## 问题

CPU Package 数据和 PawnIO 驱动持续正常，但命名管道服务每隔一秒取消当前等待并重建管道。助手使用两秒采样时，连接可能恰好落在取消边界：客户端已连接，服务端却关闭实例，客户端读到 EOF 并把本次温度标记为暂不可用。

## 决策

服务端不再以一秒为周期轮询空闲状态。每次创建管道后，直接等待到距离三十秒空闲期限的剩余时间；连接成功就发送当前快照并重新计算期限。客户端在连接后提前消失时，只放弃该次写入并继续服务，不能让 Windows 服务退出。

Rust 客户端在一个采样周期内最多读取三次，失败后等待四十毫秒再试，总额外等待不超过八十毫秒。重试只处理瞬时连接和 EOF，不缓存上一次温度，也不把过期数值伪装成实时数据。服务未安装、PawnIO 缺失、初始化失败等现有明确状态保持不变。

## 验证

.NET 测试验证服务按配置的短空闲期限及时停止，不再被固定一秒轮询拖延。Rust 测试验证前两次失败、第三次成功时返回本周期结果。发布版本提升至 0.1.2，执行格式检查、严格 Clippy、全工作区测试、.NET 测试和完整 WiX Bundle 构建。界面是否持续稳定显示由用户安装后人工观察。
