# 精确温度引擎设计

日期：2026-08-02
状态：已确认

## 目标与边界

- CPU 只显示可识别的 `CPU Package` 或 AMD `Tctl/Tdie` 温度。
- GPU 只显示目标显卡的 `GPU Core/Edge` 温度，不采集 Hot Spot/Junction。
- 完全删除 ACPI 热区读取，不再把机身、主板或固件热区标为 CPU 温度。
- 存在独立显卡时只显示独显；没有独显时才显示核显。
- 真实传感器不存在或服务不可用时诚实降级，不估算、不跨设备回退。

## 架构

桌面程序继续以普通用户运行。安装包一次性提权，在 `%ProgramFiles%\ZZH Desktop Assistant` 安装桌面程序和按需启动的 `ZZHSensorService`。服务以受限的本机 Windows 服务身份加载 `LibreHardwareMonitorLib 0.9.6`，维护每两秒更新一次的温度快照；没有客户端访问 30 秒后停止。

桌面端首先按 DXCore 选择目标物理显卡类别和厂商。GPU 温度优先使用厂商能力；当前 Intel Level Zero 路径继续保留，NVIDIA/AMD 的不可用路径由传感器服务补充。服务返回所有受支持厂商的 Core/Edge 值，桌面端只接受与已选目标厂商一致的数据。CPU 只接受明确的 package/control-die 名称白名单。

## IPC 与安全

服务创建只出不进的本机命名管道 `ZZHDesktopAssistant.Sensor.v1`。每次连接只发送一个长度受限的 UTF-8 JSON 快照后断开，不接收命令、路径或参数。管道 ACL 只允许 `SYSTEM` 和本机内置用户读取。桌面端限制消息为 16 KiB、限制集合数量、验证协议版本、有限温度范围和已知厂商 ID，解析失败只影响温度指标。

安装时服务设置为手动启动，并只授予普通本机用户查询与启动权限，不授予停止、修改配置或删除权限。卸载必须停止并删除服务及文件。服务和桌面端不记录原始硬件序列号、API Key 或用户内容。

## 数据模型

服务快照包含协议版本、生成时间、可选 CPU 读数和有限 GPU 列表。每个读数包含摄氏度、规范化传感器类别、厂商 ID 和数据源。桌面快照保留数值与来源枚举，UI 显示 `CPU Package · LHM`、`GPU Core · Intel Level Zero` 或 `GPU Core · LHM` 等简短说明。

## 失败与降级

- 服务未安装：CPU 显示“不支持 / 未安装传感器服务”。
- 服务正在启动或管道暂时失败：显示“暂不可用 / 传感器服务连接失败”。
- 内核驱动被 Windows 安全策略拦截：显示“不支持 / CPU Package 读取受限”。
- 厂商原生 GPU 接口失败：只允许同一目标厂商的 LHM Core/Edge 回退。
- 只有 Hot Spot/Junction：GPU 温度显示不支持，不拿热点值代替核心温度。

## 非功能目标

- 温度采样间隔不短于 2 秒；隐藏状态不提高采样频率。
- 服务空闲 CPU 目标低于 0.5%，工作集以 60 MiB 为验收警戒线。
- 管道连接和读取不得阻塞现有系统监控线程超过 250 ms。
- 安装包为 Windows 10/11 x64；服务使用 .NET 8 自包含单文件，不要求目标机安装运行时。
- LibreHardwareMonitor 的 MPL-2.0 许可证、版本和源码地址随安装包分发。

## 验证

自动测试覆盖传感器白名单、Hot Spot 排除、目标厂商匹配、协议大小/版本/异常值、服务失联与恢复。实机验证由用户手动完成：分别在空闲、CPU 负载和 GPU 负载下与 HWiNFO 的同名 `CPU Package`、`GPU Core/Edge` 传感器对照，并检查服务启停、普通用户启动权限和卸载清理。
