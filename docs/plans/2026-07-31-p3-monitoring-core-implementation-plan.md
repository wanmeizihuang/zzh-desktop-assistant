# P3 监控核心实施计划

**状态：** 已关闭（2026-07-31，界面与显示内容改由用户人工确认）

**目标：** 在现有 Windows 原生采样器基础上，交付准确、低开销、可降级并带 5 分钟历史趋势的监控核心。

**架构：** `system-monitor` 负责指标状态、时间语义、采样和有界历史；桌面应用只消费不可变快照，并根据窗口可见性决定刷新和趋势重绘频率。单项数据源失败不得中断其他指标。

**技术栈：** Rust 1.97.1、windows-rs、Slint 1.17.1，不新增常驻进程。

---

### Task 1：统一指标状态与时间语义

**状态：** 完成（2026-07-31）

1. 为快照增加单调采样时间。
2. 区分预热、不支持和暂时错误状态。
3. 定义快照过期判断并覆盖边界测试。
4. 保持现有 CPU、内存、网络、GPU、显存和温度 UI 兼容。

### Task 2：5 分钟有界历史

**状态：** 完成（2026-07-31）

1. 实现按时间窗口淘汰的环形历史容器。
2. 覆盖空历史、边界保留、过期淘汰和时间倒退测试。
3. 将监控 worker 的采样结果写入历史，但暂不增加额外采样线程。

### Task 3：采样正确性与恢复

**状态：** 完成（2026-07-31）

1. 对照 Windows 系统工具验证 CPU、内存和网络。
2. 区分 GPU/显存不支持与暂时读取错误。
3. 覆盖计数器重置、网卡切换、休眠后的大时间间隔和恢复逻辑。

### Task 4：趋势图

**状态：** 完成（2026-07-31）

1. 从 5 分钟历史生成固定点数的降采样序列。
2. 只在监控页可见时更新 Slint 图表模型。
3. 展示 CPU、内存和网络趋势，并明确缺失数据区间。

### Task 5：可见性降频与性能优化

**状态：** 完成（2026-07-31）

1. 展开监控页保持交互刷新频率，收起或隐藏时降低采样/UI 更新频率。
2. 避免隐藏窗口重绘趋势和无意义的跨线程 UI 调度。
3. 调整动态形象刷新策略，记录空闲 CPU、工作集和私有内存。

### Task 6：兼容矩阵与 P3 质量门禁

**状态：** 阶段关闭处理完成（2026-07-31）

1. 记录 NVIDIA、AMD、Intel 和无独显设备的能力与降级行为。
2. 运行格式、测试、严格 Clippy 和 Release 构建。
3. 输出系统工具对照和资源占用报告，确认 P3 验收结论。

关闭说明：格式、测试、严格 Clippy、Release 构建、系统工具对照和当前设备资源采样已完成。用户决定 P3 的界面操作及显示内容验证改为人工处理并批准关闭阶段；NVIDIA、AMD、Intel 与无独显设备矩阵并入 P6，不作为 P3 阻断项。
