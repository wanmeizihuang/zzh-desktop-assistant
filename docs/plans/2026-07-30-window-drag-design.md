# P1 窗口拖动设计

日期：2026-07-30

## 范围

本轮完成收起态和展开态拖动，并避免拖动结束后误触发收展。位置锁定、位置持久化、跨显示器恢复和工作区级边缘修正仍属于 P2。

## 方案比较

1. Slint 指针移动时手动设置窗口坐标：实现直观，但每次移动都跨 UI/Rust 边界，DPI 和鼠标相对坐标容易产生抖动。
2. Winit 原生 `drag_window()`：复用 Windows 系统拖窗循环和多屏 DPI 行为，没有常驻轮询，资源开销最低。
3. 替换 Win32 窗口过程处理 `WM_NCHITTEST/WM_MOVING`：控制最完整，但需要不安全代码和窗口过程生命周期管理，不适合当前验证阶段。

采用方案 2。Slint 仅上报按下和移动坐标；Rust 状态模型在位移达到 5 个逻辑像素后只触发一次原生拖动。未达到阈值的收起态手势仍作为点击展开。展开态只允许从顶部标题区拖动，右上角收起按钮和页签保留各自交互。

## 可见范围

监听 Winit `Moved` 事件。窗口超出当前显示器时，将位置夹取到至少保留 32 个物理像素可见的范围。该约束用于防止窗口完全丢失；任务栏工作区、显示器热插拔和持久化位置将在 P2 处理。

## 验证

- 单元测试覆盖手势阈值、只触发一次、下一次按下重置及轻微移动仍可点击。
- 单元测试覆盖窗口四边越界和正常位置不变。
- 真实窗口验证收起态拖动、点击展开、标题区拖动、右上角收起及 150% DPI 尺寸往返。
