# P1 核心指标采样设计

日期：2026-07-30

## 范围

本轮接入 CPU 总占用、物理内存和所有已启用非回环网卡的上下行速率。GPU、显存和温度继续明确显示“待接入”，不使用负载推算或演示数值。

## 方案比较

1. 使用 `sysinfo`：跨平台且开发快，但会引入额外刷新模型，难以精确控制 Windows 数据源和常驻开销。
2. 使用 PDH：适合性能计数器和多实例，但英文/本地化计数器、实例管理与启动预热更复杂。
3. 直接调用 Windows API：`GetSystemTimes`、`GlobalMemoryStatusEx` 和 `GetIfTable2` 足以覆盖当前范围，依赖和采样成本最低。

采用方案 3。`system-monitor` crate 提供统一 `MetricSnapshot`，每项带“可用、预热、不可用”状态。CPU 和网络按两次累计值与真实时间间隔做差分，计数器回退时按 0 处理。内存使用量由总物理内存减可用物理内存得到。

## 线程与数据流

桌面端启动一个采样线程，首次等待 250 ms，之后每 2 秒采样。每个快照通过 Slint 的线程安全事件循环入口投递到 UI，不在 UI 线程调用系统 API，也不增加高频轮询定时器。退出时发送停止信号并等待线程结束。

## 降级与验证

单项 API 失败只把该指标标为不可用。CPU/网络首次缺少差分基线时显示“采样中”。纯逻辑测试覆盖 CPU 差分、网络速率、计数器回退和内存使用量；真实 Windows 验证与系统 API/PowerShell 对照，并重新测量收起态工作集与空闲 CPU。
