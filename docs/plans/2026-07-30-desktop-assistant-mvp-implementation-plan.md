# 桌面助手 MVP Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在 2026-10-23 前交付一个可安装、可长期驻留的 Windows 桌面助手 MVP，完成低资源硬件监控、多智能体问答和安全文件拖放。

**Architecture:** 使用 Rust 模块化单体和 Slint 原生 UI。基础监控位于主进程；温度兼容层和智能体 CLI 以按需子进程运行；智能体通过能力驱动的统一连接器接入。

**Tech Stack:** Rust stable、Slint、Tokio、windows-rs/Win32、reqwest、serde、tracing、Windows Credential Manager、可选 LibreHardwareMonitor 桥接、cargo-nextest。

## 6. 进度更新规则

每次完成一个阶段任务后更新本文档，不把“代码已写但未验证”计为完成。

完成定义：

1. 功能代码和对应测试均提交。
2. 格式检查、静态分析和相关测试通过。
3. 可运行演示或可复现命令已提供。
4. 性能敏感功能附资源数据。
5. 已知限制和失败模式已记录。

状态规则：

- `未开始`：尚未产生可验证交付物。
- `进行中`：已有实现，但阶段验收条件未全部通过。
- `受阻`：缺少外部接口、硬件、凭据或产品决策，且模拟方案不能继续降低风险。
- `已完成`：阶段验收条件全部通过。

界面验证规则（2026-07-31 用户确认）：后续需要桌面界面操作或显示内容确认时，开发侧只提供可复现的人工验证步骤，不自动点击、截图或控制用户桌面；由用户执行并反馈结果。
