# P4 智能体交互设计

日期：2026-07-31
状态：已确认，进入实现

## 目标与边界

P4 交付一个可在桌面助手中切换、发送、流式显示、停止和重试的智能体对话闭环。首批正式支持 OpenAI 兼容 HTTP 与 Codex CLI；千问、豆包和 DeepSeek 在 P5 作为经过验证的配置预置接入。对话历史默认只保存在内存中，应用退出后清空。文件附件仍属于 P5，本阶段仅保留能力声明和发送前拒绝逻辑。

## 架构

`agent-core` 冻结传输无关契约，并新增严格的运行状态归约器：只接受同一请求 ID 的 `Started → TextDelta* → Completed/Cancelled/Failed` 序列，拒绝开始前文本、重复开始、终态后事件和跨请求污染。连接器目录保存少量 `Arc<dyn AgentConnector>`，按稳定 ID 提供切换，不让 UI 认识 HTTP 或 CLI 实现。

`agent-http` 实现 OpenAI 兼容的流式连接器，复用单个 HTTP 客户端，在按需工作线程中解析 SSE。测试使用本机模拟服务覆盖成功分片、断流、超时、401、429、畸形事件和超长响应，不依赖真实密钥。`agent-cli` 在现有安全子进程原型上增加 Codex 参数构造、可执行文件探测和输出适配，继续禁止 shell 拼接。

桌面端只允许一个活动请求。发送后由后台 worker 消费 `AgentEvent`，事件进入 Slint 前先通过归约器；停止调用幂等取消，失败后仅在错误可重试时保留重试入口。API Key 存入 Windows Credential Manager，JSON 配置只保存凭据引用和非秘密连接参数。所有日志与错误展示必须脱敏。

## 错误与资源策略

- 配置错误、认证失败、限流、超时、传输、协议和进程错误保持机器可读分类。
- HTTP 与 CLI 仅在用户发起请求时创建工作任务，不新增空闲常驻运行时。
- 响应文本设有有界容量，界面使用增量更新与后续虚拟化，避免超长回答无界占用。
- 切换智能体不自动发送；活动请求期间禁止切换，必须先停止或等待终态。
- 重试复用上一条用户请求，但生成新的请求 ID，避免旧事件污染新运行。

## 验证规则

协议、传输、凭据和状态机使用自动化测试。涉及桌面输入、智能体切换、流式文本、停止按钮和错误展示时，只提供人工验证步骤与预期结果，由用户手动执行确认，不自动操作或截图用户桌面。
