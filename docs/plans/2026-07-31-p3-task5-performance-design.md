# P3 Task 5 可见性降频与性能优化设计

日期：2026-07-31
状态：已确认，进入实现

## 目标与边界

本批降低助手收起和隐藏时的后台开销，同时保证用户展开监控页后立即看到新数据。沿用现有单个监控线程和 Slint 事件循环，不增加常驻进程、异步运行时或新的持久化设置。5 分钟历史仍按实际样本时间保存；降频后历史点会更稀疏，但不会补造数据。

## 方案

监控线程新增三态活动模型：展开且位于监控页为 `Interactive`，收起或展开在其他页签为 `Background`，托盘隐藏为 `Hidden`。对应采样周期分别为 2 秒、10 秒和 20 秒。隐藏周期低于采样器 30 秒的差分失效边界，为 Windows 线程调度留下余量。UI 状态变化通过控制通道发送给监控线程；切换到 `Interactive` 时立即采样，切换到后台状态时立即采用新周期。相比每轮跨线程读取 UI 状态，该方案在收起和隐藏时不会产生无意义的 UI 任务。

只有 `Interactive` 样本会构造趋势模型并进入 Slint 事件循环。事件循环真正应用数据前再次检查窗口可见、面板展开和监控页签，覆盖“采样后立刻隐藏”的竞态。恢复到监控页时立即采样并一次性更新指标与趋势。

动态形象继续在隐藏时完全停止。可见收起态从约 15 FPS 调整为 10 FPS；展开态的小尺寸形象调整为 5 FPS。设置页的两个候选预览固定在首帧，只让实际选中的主形象动画，减少每帧重绘面积。

## 验证

单元测试覆盖 UI 状态到活动模式的映射、三种采样周期和 UI 调度资格。完整运行格式检查、工作区测试、严格 Clippy、Release 构建与空白检查。由于根目录旧版程序仍在运行，本批先记录旧版资源基线；新版真实桌面资源对照在替换根目录 EXE 后补测。
