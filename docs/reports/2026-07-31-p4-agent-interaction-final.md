## 人工验证步骤

以下步骤由用户在交互桌面执行，开发流程不自动操作窗口。

1. 通过托盘菜单退出旧进程，运行项目根目录 `desktop-assistant.exe`，点击形象并进入“对话”页。
   预期：默认显示 `Codex CLI`；已安装且可从 `PATH` 找到时状态为可用，否则明确显示不可用，程序不崩溃。
2. 点击智能体选择区；若配置超过 4 个档案，滚轮向下浏览并选择另一个档案。
   预期：菜单可滚动，可用与不可用状态清晰；选择后名称和状态立即更新，重启后仍选中相同档案。
3. 选择可用的 Codex 或 HTTP 档案，输入中文问题并按 Enter 或发送按钮。
   预期：输入框清空，用户消息和智能体占位气泡出现，状态依次显示“正在连接”“正在回答”“已完成”，回答连续增长而非重复整段。
4. 在回答过程中再次打开智能体选择区并重复点击停止。
   预期：活动请求期间选择区不可操作；首次停止显示“正在停止”，重复操作不产生第二个运行或错误，终态显示“已停止”。
5. 配置一个不可连接的本地 HTTP 地址并发送问题。
   预期：出现传输错误和重试按钮；点击重试后创建新运行，不重复追加用户问题，也不接收旧运行的迟到文本。
6. 配置一个不存在的 `credential_reference.target` 后重启。
   预期：档案仍在列表中但标记“缺少凭据/不可用”，发送控件禁用，界面和日志不出现任何 API Key。
7. 使用能返回多段长文本的测试智能体连续提问，滚动对话列表。
   预期：气泡文字不重叠、不越界，列表可滚动，窗口尺寸稳定；超过回答上限时请求受控失败并停止传输。
8. 请求进行中通过托盘退出程序。
   预期：程序正常退出，对应 HTTP 任务或 Codex 子进程被取消，不残留 `desktop-assistant.exe` 或本次 Codex 子进程。
