# P1 窗口原型验证报告

日期：2026-07-30
平台：Windows 11 x64，144 DPI（150% 缩放）
工具链：Rust 1.97.1 stable、Slint 1.17.1

## 验证范围

- 收起态透明、无边框、置顶窗口。
- 晓曦 PNG 以 `contain` 完整显示，不裁剪素材。
- 点击从 200 x 200 收起态切换到 412 x 640 展开态。
- 右上角按钮可从展开态返回 200 x 200 收起态。
- 收起态整张角色和展开态顶部标题区支持系统原生拖动。
- 5 个逻辑像素以内仍判定为点击，拖动后不误触发收展。
- 窗口越界时至少保留 32 个物理像素在当前显示器内。
- 监控、对话、设置三个页签的基础布局。
- release 构建的启动、内存、线程和短时空闲 CPU 基线。

## 结果

| 项目 | 结果 |
|---|---:|
| 收起态逻辑尺寸 | 200 x 200 |
| 展开态逻辑尺寸 | 412 x 640 |
| 150% DPI 收起态物理尺寸 | 300 x 300 |
| 150% DPI 展开态物理尺寸 | 618 x 960 |
| 窗口句柄首次可用 | 约 132 ms |
| 收起态工作集 | 约 22.2 MB |
| 收起态私有内存 | 约 7.0 MB |
| 展开态工作集 | 约 26.3 MB |
| 展开态私有内存 | 约 9.3 MB |
| 5 秒空闲 CPU 平均值 | 约 0.08% |
| 运行线程数 | 8 |
| release 可执行文件 | 约 11.0 MB |

CPU 百分比已按采样时长和逻辑处理器数量归一化。以上是单机短时技术基线，不替代后续冷启动、多硬件、24 小时和 7 天稳定性测试。

## 技术结论

Slint 默认同时启用 OpenGL、软件渲染与辅助访问时，收起态工作集约 144 MB，不满足目标。改为 Winit + 软件渲染 + 系统字体后，收起态降至约 22 MB，窗口与 PNG 透明度仍正常，当前方案可继续验证。

辅助访问功能暂未启用。这是 P1 的已知权衡，必须在 P2 重新验证其资源开销，并决定恢复 Slint accessibility 或使用更窄的 Windows 原生实现。

## 拖动回归

真实鼠标输入在 150% DPI 下完成以下往返：

```text
收起态拖动：304,304 -> 414,377，尺寸保持 300 x 300
单击展开：414,377，尺寸变为 618 x 960
标题区拖动：414,377 -> 322,432，尺寸保持 618 x 960
按钮收起：322,432，尺寸恢复 300 x 300
强制移出屏幕：-10000,-10000 -> -268,-268，保留 32 像素可见
```

加入拖动后再次采样，收起态工作集约 22.2 MB、私有内存约 7.0 MB、8 个线程；5 秒内 CPU 和内存均未测得增长。
