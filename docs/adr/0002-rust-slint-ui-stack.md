# ADR-0002：Rust + Slint 主技术栈

## 状态

待技术验证

## 背景

产品最重要的非功能指标是常驻内存、空闲 CPU、启动时间以及透明置顶窗口体验。UI 同时需要中文输入、多屏 DPI、拖放和无障碍支持。

## 决策

技术验证阶段使用 Rust 实现核心和 Windows 集成，使用 Slint 实现原生 UI。只有在透明窗口、中文输入、无障碍或资源指标通过基准测试后，才将本决策改为“接受”。

## 影响

### 正面

- 原生编译，运行时和启动成本可控。
- Rust 适合处理长时间运行、并发采样和外部输入边界。
- Slint 不需要常驻 Chromium 进程。

### 负面

- Windows 特殊窗口行为和硬件适配需要更多底层开发。
- 团队需要同时掌握 Rust、Slint 和 Windows API。
- 生态和可用组件少于 Web 或 WPF。

## 备选方案

- Electron：开发效率高，但常驻资源目标风险最大。
- .NET 8 WPF：Windows 集成和库生态成熟，是验证失败后的首选回退。
- C++/WinUI 或 Qt：控制力强，但内存安全、构建和维护成本更高。
