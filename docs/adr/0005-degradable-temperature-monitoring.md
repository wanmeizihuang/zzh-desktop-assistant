# ADR-0005：可降级的温度监控

## 状态

建议接受

## 背景

Windows 没有覆盖所有 CPU、GPU 和主板的统一温度接口。不同厂商 API、驱动版本、权限与设备传感器会造成兼容性差异。

## 决策

基础指标使用 Windows 原生接口；GPU 温度优先使用可动态探测的厂商接口；CPU/主板和其他温度通过可选传感器桥接进程补充。任何温度源不可用时只降级对应指标，并显示原因，不阻断基础监控。

## 影响

### 正面

- 核心程序不必长期加载额外运行时或高风险硬件库。
- 传感器故障不会导致整个助手退出。
- 能诚实呈现硬件能力，避免不可靠的估算值。

### 负面

- 不同电脑展示的传感器项目可能不同。
- 可选桥接会增加安装体积和峰值内存。
- 需要持续维护硬件兼容矩阵。

## 备选方案

- 仅用 Windows 标准接口：体积最小，但温度覆盖率不足。
- 所有用户都常驻 LibreHardwareMonitor：覆盖较好，但增加资源和运行时依赖。
- 自行实现所有硬件寄存器访问：覆盖成本和安全风险过高，不采用。
