# ADR-0003：能力驱动的智能体连接器

## 状态

建议接受

## 背景

Codex、千问、豆包、DeepSeek、Hermes、WorkBuddy 的认证方式、文件支持、流式协议和运行位置不同。品牌名称不能构成稳定的技术接口。

## 决策

定义统一连接器协议和能力声明。首期实现 OpenAI 兼容 HTTP、厂商官方 HTTP、本地 CLI 三种连接方式；品牌预置只是经过测试的配置模板。UI 根据连接器声明决定是否允许文件、图片、流式输出和本地路径。

## 影响

### 正面

- 新智能体只需实现连接器契约，不侵入 UI 和核心流程。
- 不支持的功能在发送前即可阻止。
- 可以用统一契约测试降低厂商接口变更风险。

### 负面

- 不能宣称所有品牌具有完全一致的能力。
- 需要维护厂商版本、能力和兼容矩阵。

## 备选方案

- 每个品牌单独写 UI 与调用逻辑：短期直接，长期重复且难测试。
- 只支持 OpenAI 兼容 API：实现简单，但无法覆盖官方协议和本地 CLI。
- 网页自动化：无需官方接口，但脆弱、难维护且可能违反服务条款，不作为正式方案。
